# 구현 진행보고

## 현재 상태 (2026-11-12)

M1~M6 기준 커밋은 `a292472`. 이어받은 미커밋 M7 UI·파일 API·테스트를 보존해 검토했다. 토큰은 메모리에만 저장하고 인증 세션마다 QueryClient를 교체한다. 기본 임베딩은 무료 로컬 bge-m3, 답변은 fake다. push는 수행하지 않았다.

## M7 검증

- API: `cd apps/api && uv run pytest` → 112 passed, 4 integration deselected. `uv run ruff check app tests`, `uv run mypy app` 통과.
- 웹: `cd apps/web && npm run typecheck && npm test && npm run lint && npm run build` (최종 결과는 handoff 참조).
- 브라우저: 실제 로컬 API·Qdrant·OpenSearch·bge-m3와 Chrome에서 로그인→PDF 업로드→ready→질문→근거 카드→PDF 3/3쪽→보류 화면 통과. fake 답변은 품질 평가가 아니다.
- `docker compose config`는 저장소 내부 standalone Compose로 검증. Docker daemon이 없어 컨테이너 기동·이미지 빌드 검증은 미실행.
- M8 범위의 파일 API는 M7 PDF 뷰어 검증에 필요하여 선행 구현. 요청마다 권한·ready 상태 확인, 전체/Range 응답 및 경로 이탈 방어 테스트 포함.

## 실행

Docker 환경: `cp .env.example .env` 후 `.env`의 AUTH_SECRET 설정, `docker compose up --build -d`. 로컬 검증은 `infra/local/README.md` 참조. 기존 개발 서버는 API 8000, 웹 5173이며 `infra/local/api.sh`의 기본 포트는 8010이므로 웹 프록시와 맞춰 8000을 지정한다.

## 남은 작업과 리스크

M8 삭제·재시도·캐시 골격·격리 회귀부터 순서대로 진행. M1 컨테이너 기동·메모리, M4/M6 유료 API smoke는 기존 미검증 상태를 유지한다. M9~M12 평가·성능·보안·CI 및 선택 M13은 아직 완료하지 않았다.
